# Reproducing the qclip v1 results

`qclip-v1` is the reproducibility release for the LREC 2026 paper *Meaning Representations as Variational Quantum
Circuits*. It contains the code, the configs, the exact data splits, the trained weights of the CCG-VQC and the raw
per-run results behind every number in the table below. Everything here is the post-selected (PS) model; the
discard/hardware variants live on other branches.

## Results

seeds 0–4 (one run per split; run k = split k = training seed k). Text parameters only: every trained model uses the same frozen CLIP ViT-B/32 image vector, so no image
parameters are trained. Generated by `python scripts/summarise_v1.py results/v1` (`results/v1/summary.md`).

## 1. Environment

`pip install -r requirements.txt` (Python 3.12). Training used one NVIDIA GPU per run (L40S / A100 / A6000 / RTX 6000
Ada class, 40–80 GB); MicroCLIP-16 on SVO ran on CPU. Never import or run lambeq: captions are parsed with the Bobcat
parser through `modules/symbolic/text_processor.py`, and cup removal is the curried ansatz (`text.curry: true`).

- **SVO-Probes** (Hendricks & Nematzadeh, 2021) is released for evaluation only. Our pool is 8,929 of DeepMind's rows,
  curated and rewritten as simple subject–verb–object sentences (`modules/data_pipeline/manifests/svo-probes/`), with
  CCG parses and CLIP ViT-B/32 image embeddings. Images are fetched from their original URLs; some links have died
  since our download, so a fresh `retrieve.py` drops those pairs and the splits come out slightly smaller than below.
  Expect small differences in that case.
- **ARO** (Yuksekgonul et al., 2023): VG-Attribution and VG-Relation, every image cropped to its row's box as in the
  official evaluation. Training never uses ARO's hard negatives.
- Images are not redistributed here (third-party sources); `retrieve.py` rebuilds the embeddings.

## 3. Splits

Neither dataset has an official training split. `modules/data_pipeline/splits.py` assigns groups by a hash of
(seed, group): every caption of a positive image (SVO-Probes, 60/20/20) or every row of a Visual Genome image (ARO,
70/15/15) lands in one split. The vocabulary is then closed: a val/test group with a word no training caption has moves
to train. On SVO-Probes, the 60 images of SVO-Swap's 95 pairs are pinned to test on every seed (`test_always: swap95`),
so the swap pairs are never trained on or used for model selection.

`splits/<dataset>/seed<k>.csv` lists every pool row (its position in `all.pkl`), its split and its membership of each
test set; `splits/<dataset>/records.json` holds the split records and the pool md5
(`python scripts/export_splits.py --dataset <dataset> --seeds 0 1 2 3 4 -o splits/<dataset>`). Every run also stores
its split record in its `config.yaml`, and evaluating a checkpoint on a different split raises an error.

## 4. Test sets and metric

- **std** (SVO-Probes): choose the positive image over the negative image for a caption.
- **SwapFull**: choose the caption over its subject/object swap, for every test caption with two nouns (symmetric verbs
  and unchanged swaps dropped; `datasets.build_swap_set`).
- **Swap95**: the paper's SVO-Swap, 95 pairs whose two nouns are people or animals, rebuilt by `datasets.select_swap95`.
- **Attribution / Relation** (ARO): choose the caption over its attribute or relation swap.

Accuracy is `hard_neg_acc_norm_tie_half` for every trained model: the score is the overlap of the **unit-normalised**
text and image states (fidelity for the VQC, cosine for the classical models), correct when the positive scores higher,
a tie counts ½ (QBoW ties on every swap, as it ignores word order). Zero-shot models use their own score (cosine, BLIP ITM).
Normalising matters for text choice (SwapFull, Swap95, Attribution, Relation: one image, two captions): the raw overlap
`|<i|t>|` scales with the caption's norm (for post-selection, its success amplitude), which does not depend on the image,
so a model can win a text choice from the captions alone. The raw `hard_neg_acc_tie_half` and strict `hard_neg_acc` are
stored next to it; for the v1 models they differ by at most 0.017.

## 5. Models

All trained models use the frozen CLIP ViT-B/32 image vector (512-d). Quantum models amplitude-encode it on 9 qubits
(`vision.method: amp`); classical models use it as a unit vector.

- **CCG-VQC** (`configs/v1/<dataset>/ps.yaml`): each word is a `custom_v5` circuit (H, then per layer Rz·Ry·Rz on every
  qubit and a CX ring) on its CCG type's wires, wired along the sentence's parse (`text.curry: true`), with the
  sentence read out on 9 qubits by post-selection. Fubini–Study InfoNCE (temperature 0.07, label smoothing 0.1), Adam,
  learning rate 0.01, batch 256 (SVO) / 512 (ARO), up to 100 epochs, cosine schedule with 5 warm-up epochs, early
  stopping on validation accuracy (patience 12); the best-validation checkpoint is tested.
- **Size search** (split 0, validation only; the config headers list every value):
  - SVO, 3 qubits per type: 3 layers 0.646, 4 layers 0.672, **5 layers 0.709**; 2 qubits/5 layers 0.684;
    4 qubits/4 layers 0.643; 6 layers does not fit in 24 h.
  - ARO: 3 qubits per type, **3 layers 0.572**; 4 layers 0.549; 5 layers 0.560; 4 qubits/4 layers 0.557;
    Frobenius root (9 sentence qubits) 0.539; patience 30 gives the same 0.572.
- **QBoW** (`qbow.yaml`): every word its own `custom_v5` circuit on the 9 output qubits, at the VQC's depth, words merged
  by Frobenius (pointwise) multiplication; word order is ignored by construction. Not parameter-matched.
- **MicroCLIP** (`microclip.yaml`): CLIP's text transformer shrunk to 2 layers and 2 heads, trained from scratch with
  the same data and an InfoNCE loss on |cosine|. Width 32 cannot reach the VQC's count (its embeddings and 32→512
  projection alone exceed it), so the width is chosen per dataset and the feed-forward width matches the count:
  width 16 / ff 88 on SVO, width 24 / ff 47 on ARO (`python scripts/count_params.py -cfg <config> --grid key=v1,v2`).
- **CCG tensor network** (`tn.yaml`): the same CCG diagrams with classical word tensors (wires 2³ = 8, output 512),
  MPS-decomposed at bond dimension 2. It cannot be parameter-matched without changing its dimensions (bond 1 is already
  335k on SVO / 283k on ARO), so its real counts are reported.
- **Zero-shot** (`scripts/zeroshot.py`): `openai/clip-vit-base-patch32`, `laion/CLIP-ViT-B-32-laion2B-s34B-b79K` and
  `Salesforce/blip-itm-base-coco` (ITM probability and, separately, ITC cosine), scored on raw images of each split's
  test rows.
- The baselines use their recipes' default learning rates (MicroCLIP and tensor network 10⁻³, QBoW 0.01); no
  learning-rate sweep was run.

## 6. Commands (one per table row)

```bash
# CCG-VQC (each writes results/v1/<tag>/k<k>.json; existing outputs are skipped)
bash scripts/run_splits.sh svo_ps_n3L5 configs/v1/svo-probes/ps.yaml "0 1 2 3 4"
bash scripts/run_splits.sh aro_ps_n3L3 configs/v1/aro/ps.yaml        "0 1 2 3 4"
# baselines
for m in qbow microclip tn; do
  bash scripts/run_splits.sh svo_$m configs/v1/svo-probes/$m.yaml "0 1 2 3 4"
  bash scripts/run_splits.sh aro_$m configs/v1/aro/$m.yaml        "0 1 2 3 4"
done
# zero-shot
python scripts/zeroshot.py --dataset svo-probes --images data/svo-probes/raw/images.zip --seeds 0 1 2 3 4 -o results/v1/zeroshot_svo
python scripts/zeroshot.py --dataset aro        --images data/aro/raw/crops.zip        --seeds 0 1 2 3 4 -o results/v1/zeroshot_aro
# table
python scripts/summarise_v1.py results/v1
```

Set `PY` (and optionally `X`, a container prefix) for `run_splits.sh`; it trains run k on split k with training seed k
and benchmarks its `best.pt`. In `results/v1` the SVO MicroCLIP runs are tagged `svo_microclip_cpu` (they ran on CPU).

**Released weights.** `weights/v1/<dataset>/post_selection/k<k>/` holds the CCG-VQC's `best.pt`, the full resolved
`config.yaml` (seed, split record, git commit) and `metrics.json` (its test results). Re-evaluate one with

```bash
python scripts/benchmark.py -cp weights/v1/svo-probes/post_selection/k0/best.pt -o out.json
```

The SVO finals were trained at commit `7995aad`, the ARO finals at `311ee4c` and the baselines at `15c8d19`; these
differ only in configs, not in model code.
